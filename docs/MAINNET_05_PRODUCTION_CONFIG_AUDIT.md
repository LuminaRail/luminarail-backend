# MAINNET-05: Production Configuration Audit & Fail-Closed Environment Design

> **Notice**: This document audits all environment variables, security configurations, and runtime settings in the LuminaRail backend (`src/config/index.ts`, `src/app.ts`) as of commit `edb74b2`. No changes have been made to the source files during this audit.

---

## Executive Summary

Deploying a financial transaction system connecting fiat banking rails (Paystack) to public blockchain infrastructure (Stellar Mainnet) requires strict environment isolation, fail-closed configuration parsing, and zero tolerance for insecure defaults. 

Our audit of `src/config/index.ts` and `src/app.ts` identified **3 Critical Production Vulnerabilities**:
1. **Overly Permissive CORS (`app.use(cors())`)**: Allows any web origin to interact with LuminaRail backend endpoints.
2. **Dangerous Signer Fallback (`STELLAR_SIGNER_PROVIDER=testnet_local`)**: Default allow list includes local secret seed signing, risking mainnet key exposure if `NODE_ENV=production` is paired with testnet configuration defaults.
3. **Missing Mainnet Fail-Closed Network Guards**: The schema permits `STELLAR_NETWORK=mainnet` while `STELLAR_RPC_URL` defaults to `https://soroban-testnet.stellar.org`, enabling dangerous testnet/mainnet network parameter mixing.

## 1. Environment Variable Classification Matrix

Every configuration variable defined in `src/config/index.ts` is classified into one of five categories:
* **TESTNET ONLY**: Must NEVER be present or enabled in production.
* **PRODUCTION REQUIRED**: Mandatory for production; system must fail to boot if missing.
* **SAFE DEFAULT**: Pre-configured default is mathematically and security-safe for production.
* **DANGEROUS DEFAULT**: Present in code, poses severe security or financial risk if unchanged in production.
* **MUST FAIL-CLOSED**: Invalid or missing value must halt application startup immediately.

## 2. Identified Insecure Configurations & Production Risks

### 2.1 Overly Permissive CORS Configuration (`src/app.ts`)
* **Current Code**: `app.use(cors());`
* **Vulnerability**: Invoking `cors()` without options defaults `Access-Control-Allow-Origin` to `*`. This permits any origin domain (including malicious phishing sites) to issue cross-origin requests to LuminaRail backend APIs using an authenticated user's credentials.
* **Production Requirement**: Must restrict CORS to strictly whitelisted domain names via environment configuration (`CORS_ALLOWED_ORIGINS`).

```typescript
// Recommended Production CORS Configuration
const allowedOrigins = process.env.CORS_ALLOWED_ORIGINS 
  ? process.env.CORS_ALLOWED_ORIGINS.split(',') 
  : ['https://app.luminarail.com'];

app.use(cors({
  origin: (origin, callback) => {
    if (!origin || allowedOrigins.includes(origin)) {
      callback(null, true);
    } else {
      callback(new Error('CORS policy violation: Origin not allowed.'));
    }
  },
  credentials: true,
  methods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS'],
  allowedHeaders: ['Content-Type', 'Authorization', 'X-Correlation-ID'],
}));
```

### 2.2 Accidental Testnet / Mainnet Mixing Hazards
* **Current Gap**: `Zod` validation validates string formats (e.g. valid Ed25519 key), but does NOT validate network consistency across fields.
* **Hazards**:
  1. Setting `STELLAR_NETWORK=mainnet` while `STELLAR_RPC_URL` is pointing to `soroban-testnet.stellar.org`.
  2. Setting `STELLAR_NETWORK=mainnet` while `STELLAR_USDC_ISSUER` is set to the Testnet USDC address (`GBBD47IF6LWK7P7MDEVSCWR7DPUWV3NY3DTQEVFL4TW45BCUXG6V2ZOL`).
  3. Setting `NGN_PROVIDER=paystack` while `PAYSTACK_SECRET_KEY` starts with `sk_test_`.
* **Production Requirement**: Add strict multi-field refinement rules in `src/config/index.ts` to prevent boot if environment parameters cross networks.

## 3. Recommended Production Zod Validation Refinements

```typescript
// Proposed Fail-Closed Zod Additions for Production Boot Validation

export const envSchema = z.object({
  // ... existing definitions
}).refine((data) => {
  // Prevent Testnet Local Signer in Production
  if (data.NODE_ENV === 'production' && data.STELLAR_SIGNER_PROVIDER === 'testnet_local') {
    return false;
  }
  return true;
}, {
  message: 'STELLAR_SIGNER_PROVIDER cannot be "testnet_local" when NODE_ENV is "production". Must use aws_kms, gcp_kms, or fireblocks.',
  path: ['STELLAR_SIGNER_PROVIDER'],
}).refine((data) => {
  // Prevent Testnet Stellar RPC in Mainnet Production
  if (data.STELLAR_NETWORK === 'mainnet' && data.STELLAR_RPC_URL.includes('testnet')) {
    return false;
  }
  return true;
}, {
  message: 'STELLAR_RPC_URL cannot point to testnet when STELLAR_NETWORK is set to mainnet.',
  path: ['STELLAR_RPC_URL'],
}).refine((data) => {
  // Enforce Mainnet USDC Issuer Address
  const MAINNET_USDC_ISSUER = 'GA5ZSEJYB37JRC5AVCI5M4GEKG2CAXA5PYW5RKAC4QPSTM72ZUYBXJLY';
  if (data.STELLAR_NETWORK === 'mainnet' && data.STELLAR_USDC_ISSUER !== MAINNET_USDC_ISSUER) {
    return false;
  }
  return true;
}, {
  message: 'STELLAR_USDC_ISSUER must be set to the official Stellar Mainnet USDC issuer (GA5ZSEJYB37JRC5AVCI5M4GEKG2CAXA5PYW5RKAC4QPSTM72ZUYBXJLY) when STELLAR_NETWORK is mainnet.',
  path: ['STELLAR_USDC_ISSUER'],
}).refine((data) => {
  // Prevent Paystack Test Key in Production
  if (data.NODE_ENV === 'production' && data.PAYSTACK_SECRET_KEY.startsWith('sk_test_')) {
    return false;
  }
  return true;
}, {
  message: 'PAYSTACK_SECRET_KEY cannot be a test key (sk_test_...) when NODE_ENV is "production".',
  path: ['PAYSTACK_SECRET_KEY'],
});
```

## 4. Secret Exposure Prevention & Log Scrubbing Rules

### 4.1 Log Scrubbing Rules
To prevent catastrophic secret leaks to logging providers (Datadog, CloudWatch, Logtail), the logger MUST sanitize:
* `PAYSTACK_SECRET_KEY` / `x-paystack-signature`
* `STELLAR_SETTLEMENT_SIGNER_SECRET_KEY`
* `JWT_SECRET` / `Authorization: Bearer ...`
* Customer PII (BVN, NIN, Phone, Card Details)

### 4.2 Error Masking Rules
* `errorHandler.ts` currently hides error details in production (`An unexpected error occurred.`). This MUST be preserved.
* Exception stack traces MUST be stripped of environment variable dumps or raw SQL query strings containing secrets.
